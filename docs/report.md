## Лист задания и сверка плана

По разделу 4.1 методички, с. 36–38, включая таблицу 4.1, требуется реализовать двухадресный процессор фон Неймана, найти максимум массива из 6–15 элементов и вычислить сумму попарных произведений двух массивов из шести беззнаковых элементов. Обе программы обрабатывают массивы в цикле. Первое слово каждого массива содержит его длину. При свёртке обязательна длинная арифметика.

Исходный план соответствует требованиям. В листингах уточнены заголовки обоих массивов свёртки и выход из поиска максимума после первого элемента, если длина равна единице. Рабочий диапазон задания остаётся 6–15 элементов. Непосредственные операнды в арифметике разрешены, поскольку они входят в машинную инструкцию. Обращение к данным в ОЗУ выполняют MOV и XCHG.

## Устройство процессора

| Компонент | Размер | Назначение |
|---|---:|---|
| ОЗУ | 64 КиБ | Единое байтовое пространство команд и данных |
| РОН | 16 × 16 бит | Данные, указатели, промежуточные результаты |
| PC | 16 бит | Байтовый адрес следующей команды |
| IR | 32 бита | Последняя выполненная машинная команда |
| FLAGS | 3 бита | ZF, CF, SF |

Номера регистров 0–7 соответствуют AX, BX, CX, DX, SI, DI, BP, SP. Номера 8–15 соответствуют R8–R15. PC, IR, регистры, флаги и свободная память при запуске обнулены. Образ программы загружается с адреса 0. Младший байт слова хранится по младшему адресу. После обычной команды PC увеличивается на 4 по модулю 65536. Переход загружает абсолютный адрес. Команда HALT оставляет PC у следующего байта после инструкции. Чтение или запись за границей ОЗУ прерывает выполнение с сообщением.

Ассемблер определяет адреса меток первым проходом и формирует образ вторым. Ядро считывает 32 бита из ОЗУ по PC, декодирует их, выполняет операцию и возвращает снимок состояния. Консоль выводит адрес команды, IR, дизассемблированную команду, новый PC, регистры, флаги и значения памяти до и после записи.

### Связь компонентов

Ассемблер размещает инструкции и директивы DW подряд в одном образе. Таблица меток нужна при сборке: например, в `MOV SI, A` имя `A` заменяется байтовым адресом первого слова массива. При выполнении ядро использует значения из машинной команды и общего ОЗУ. Поскольку команды и данные занимают одно адресное пространство, переход должен вести на начало инструкции, а HALT останавливает процессор до области данных.

PC задаёт адрес выборки четырёх байтов. Декодер разделяет IR на код операции и поля операндов. Для `MOV CX, [SI]` ядро берёт адрес из SI, читает два байта ОЗУ и записывает слово в CX. Для `ADD SI, 2` ядро складывает значение SI с числом из PAYLOAD, сохраняет младшие 16 бит в SI и обновляет флаги. Прибавление двух переводит указатель к следующему слову.

После исполнения ядро передаёт консоли снимок состояния. В таблице трассировки звёздочка отмечает регистр или флаг, изменившийся относительно предыдущего шага. На первом шаге значения сравниваются с исходными нулями. Поля команды показаны отдельно, а запись в ОЗУ сопровождается адресом и значениями до и после операции.

## Кодирование и синтаксис

| Биты | 31–28 | 27–26 | 25–22 | 21–20 | 19–16 | 15–0 |
|---|---|---|---|---|---|---|
| Поле | OPCODE | MODE1 | OP1 | MODE2 | OP2 | PAYLOAD |

| MODE | Синтаксис | Смысл |
|---|---|---|
| 00 | `AX` | Номер регистра в OP |
| 01 | `42`, `A` | Число или адрес метки в PAYLOAD |
| 10 | `[A+2]` | Прямой адрес в PAYLOAD |
| 11 | `[SI]` | OP задаёт регистр с адресом |

Неиспользуемые поля заполнены нулями. Допустимы не более одного операнда памяти и одного операнда с PAYLOAD на команду. Например, `MOV AX, 10` кодируется словом `1010000A` и хранится байтами `0A 00 10 10`. Метки, регистры и мнемоники регистронезависимы. Поддерживаются десятичные числа, шестнадцатеричные числа с префиксом `0x`, метки со смещением и комментарии после `;`. Директива `DW` размещает 16-битные слова. В примерах данные идут после HALT.

| Код | Команда | Действие |
|---:|---|---|
| 0 | NOP | Пустая операция |
| 1 | MOV dst, src | Копирование. Назначение - регистр или память |
| 2 | XCHG dst, src | Обмен регистрами или регистром и словом памяти |
| 3 | ADD r, src | Сложение |
| 4 | ADC r, src | Сложение с входным CF |
| 5 | SUB r, src | Вычитание |
| 6 | CMP r, src | Вычитание с записью только флагов |
| 7 | MUL r | Беззнаковое AX × r → DX:AX |
| 8 | INC r | Увеличение на единицу |
| 9 | DEC r | Уменьшение на единицу |
| 10 | JMP addr | Безусловный переход |
| 11 | JE addr | Переход при ZF = 1 |
| 12 | JNE addr | Переход при ZF = 0 |
| 13 | JB addr | Переход при CF = 1 |
| 14 | JAE addr | Переход при CF = 0 |
| 15 | HALT | Остановка |

Для ADD, ADC, SUB и CMP источник - регистр или непосредственное значение. В этих командах и в INC/DEC ZF показывает нулевой 16-битный результат, SF - его старший бит, CF - перенос при сложении или заём при вычитании. У MUL ZF и SF относятся к 32-битному произведению, CF показывает ненулевую старшую половину. Остальные команды сохраняют флаги.

## Алгоритмы и проверка

Поиск максимума берёт первый элемент за начальное значение. Цикл сравнивает максимум с очередным элементом через CMP и JAE. Для исходного массива результат равен 65535 (`FFFF`).

Свёртка загружает длину первого массива и пропускает слова длины обоих массивов. Для каждой пары MUL даёт два слова произведения. ADD и две ADC передают перенос через три слова аккумулятора. Максимум суммы равен 6 × 65535² = 25 769 017 350 и требует 35 бит. Получено `0005:FFF4:0006` в порядке старшее, среднее, младшее слово.

Автоматические проверки охватывают оба алгоритма, максимум одноэлементного массива, длинное умножение и перенос, беззнаковый переход, обмен через регистр-указатель, диагностику операндов и лимит команд.

### Поиск максимума по строкам

| Строка | Действие |
|---|---|
| `MOV SI, A` | Установить указатель на слово длины. |
| `MOV CX, [SI]` | Прочитать число элементов. |
| `ADD SI, 2` | Перейти к первому элементу. |
| `MOV AX, [SI]` | Взять его за начальный максимум. |
| `DEC CX` | Учесть обработанный элемент. |
| `JE SAVE` | Сохранить максимум, если элементов больше нет. |
| `SCAN: ADD SI, 2` | Перейти к очередному элементу. |
| `MOV BX, [SI]` | Прочитать очередное значение. |
| `CMP AX, BX` | Сравнить текущий максимум с очередным значением. |
| `JAE NEXT` | Пропустить обновление, если AX ≥ BX без знака. |
| `MOV AX, BX` | Запомнить новый максимум. |
| `NEXT: DEC CX` | Уменьшить число оставшихся элементов. |
| `JNE SCAN` | Повторить цикл, пока остаются элементы. |
| `SAVE: MOV [MAX_RESULT], AX` | Записать максимум в ОЗУ. |
| `HALT` | Остановить выполнение. |
| `A: DW …` | Разместить длину и элементы массива. |
| `MAX_RESULT: DW 0` | Выделить одно слово под ответ. |

При сравнении `AX=000C` и `BX=FFFF` разность равна −65 523. Ядро выставляет CF из-за займа и сбрасывает ZF. Условие JAE ложно, поэтому следующая команда записывает `FFFF` в AX.

### Свёртка по строкам

| Строка | Действие |
|---|---|
| `MOV SI, A` | Установить указатель на начало A. |
| `MOV DI, B` | Установить указатель на начало B. |
| `MOV CX, [SI]` | Загрузить длину A. По заданию длины обоих массивов равны шести. |
| `ADD SI, 2` | Пропустить длину A. |
| `ADD DI, 2` | Пропустить длину B. |
| `MOV R8, 0` | Обнулить младшее слово суммы. |
| `MOV R9, 0` | Обнулить среднее слово суммы. |
| `MOV R10, 0` | Обнулить старшее слово суммы. |
| `DOT_LOOP: MOV AX, [SI]` | Загрузить элемент A в AX. |
| `MOV BX, [DI]` | Загрузить элемент B в BX. |
| `MUL BX` | Умножить AX на BX, сохранив произведение в DX:AX. |
| `ADD R8, AX` | Прибавить младшее слово произведения. |
| `ADC R9, DX` | Прибавить старшее слово и входной перенос. |
| `ADC R10, 0` | Прибавить перенос из среднего слова. |
| `ADD SI, 2` | Перейти к следующему элементу A. |
| `ADD DI, 2` | Перейти к следующему элементу B. |
| `DEC CX` | Уменьшить число оставшихся пар. |
| `JNE DOT_LOOP` | Начать следующую итерацию при CX ≠ 0. |
| `MOV [RESULT], R8` | Сохранить младшее слово. |
| `MOV [RESULT+2], R9` | Сохранить среднее слово. |
| `MOV [RESULT+4], R10` | Сохранить старшее слово. |
| `HALT` | Остановить выполнение. |
| `A: DW …` | Разместить длину и элементы A. |
| `B: DW …` | Разместить длину и элементы B. |
| `RESULT: DW 0, 0, 0` | Выделить три слова под ответ. |

Для `FFFF × FFFF` произведение равно `FFFE0001`. После первой пары аккумулятор равен `0000:FFFE:0001`. На второй итерации ADD даёт `0002` и CF = 0. Сложение `FFFE + FFFE` даёт `1FFFC`, поэтому R9 получает `FFFC`, а CF становится 1. Последняя ADC прибавляет этот перенос к R10. Сумма двух пар равна `0001:FFFC:0002`.

## Заключение

Реализован двухадресный процессор с единым ОЗУ и четырьмя режимами адресации. Ассемблер кодирует пользовательские программы, а эмулятор показывает состояние процессора после каждой команды. Результаты обеих задач совпали с контрольными расчётами.
